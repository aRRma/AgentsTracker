# AgentsTracker Gateway

Шлюз между Telegram и Claude Code. Работает на постоянно включённом Windows-ПК: принимает
сообщения от вашего бота, запускает `claude -p` в заданной папке проекта, спрашивает
разрешения кнопками в чате и присылает ответ агента.

Публичный IP и вебхуки не нужны — используется long polling.

## Как это устроено

```
Telegram  ──long polling──▶  ChatWorker  ──▶  claude.exe -p --output-format json --resume <id>
                                 ▲                        │
                                 │                        │ нужно разрешение
                                 │                        ▼
                            карточка              MCP http://127.0.0.1:5099/mcp
                          с кнопками  ◀────────  PermissionTool   (Authorization: Bearer <токен>)
```

Диалог непрерывный: id новой сессии шлюз выдаёт сам (`--session-id <uuid>`) и сохраняет в
`%LOCALAPPDATA%\AgentsTracker\state.json` сразу после старта процесса, а следующий запуск идёт
с `--resume <id>`. Контекст переживает перезапуск шлюза, `/stop` и падение запуска — ветка
остаётся, продолжить её можно следующим сообщением. `/new` начинает сессию с нуля.

Id сессии виден в чате: в статусной строке «⏳ Работаю… 🧵 26173332» и подписью под ответом —
полным id, который можно скопировать и продолжить с терминала: `claude --resume <id>`
в той же папке. Полностью его показывает и `/status`.

Разрешения идут через `--permission-prompt-tool`: шлюз поднимает локальный MCP-сервер, CLI
вызывает его инструмент `approve` вместо интерактивного запроса, вызов блокируется, пока вы
не нажмёте кнопку. `AskUserQuestion` приходит туда же — уточняющие вопросы агента тоже
приходят в чат вариантами ответа.

**Шлюз не подключается к сессии, открытой в VS Code.** Это отдельная параллельная сессия на
той же папке. Общие у них `CLAUDE.md`, `.claude/settings.json`, хуки, MCP-серверы проекта и
логин из `~/.claude`; история диалога — своя у каждой.

## Установка

1. **Claude Code CLI** (расширение VS Code не подходит: его бинарник лежит внутри папки
   расширения и переезжает при каждом обновлении):

   ```powershell
   irm https://claude.ai/install.ps1 | iex
   claude --version   # в новом окне PowerShell
   ```

2. **Бот**: напишите [@BotFather](https://t.me/BotFather), `/newbot`, заберите токен.

3. **Конфигурация**: скопируйте `appsettings.Local.example.json` в
   `src/AgentsTracker.Gateway/appsettings.Local.json` и заполните `BotToken` и `ProjectPath`.
   Файл рядом с проектом читается при отладке из IDE; боевое место — папка данных, см.
   «Где что лежит».

4. **Свой user id**: запустите шлюз, напишите боту что угодно — id появится в логе:

   ```
   warn: Отклонено сообщение от постороннего пользователя. user id: 123456789 …
   ```

   Впишите его в `AllowedUserIds` и перезапустите.

```powershell
dotnet run --project src/AgentsTracker.Gateway
```

## Автозапуск

```powershell
pwsh -File scripts\install-autostart.ps1
```

Регистрирует задачу Планировщика с триггером «при входе пользователя». Windows-службой под
`SYSTEM` ставить нельзя — CLI не найдёт OAuth-логин из `%USERPROFILE%\.claude`.

## Где что лежит

Всё состояние шлюза — в `%LOCALAPPDATA%\AgentsTracker\`, права на папку урезаны до владельца
и `SYSTEM`:

| Файл | Что это |
|---|---|
| `appsettings.Local.json` | боевой конфиг с секретами |
| `state.json` | выбор из чата: проект, модель, effort, режим, сессии, расход, правила «Всегда» |
| `mcp-gateway.json` | `--mcp-config` для CLI с токеном эндпоинта; пишется при старте, удаляется при остановке |
| `audit\audit-ГГГГ-ММ.jsonl` | журнал «кто, куда, что» — его показывает `/audit` |

Конфиг читается слоями: `appsettings.json` → `appsettings.Local.json` рядом с приложением
(для отладки) → он же в папке данных (боевой) → переменные окружения (`Gateway__BotToken` и т. п.).

`BotToken` и `Proxy` хранятся зашифрованными DPAPI (`dpapi:…`) — расшифровать их может только
ваша учётная запись на этой машине:

```powershell
dotnet run --project src\AgentsTracker.Gateway -- protect-secrets
```

Команда шифрует секреты и переносит конфиг в папку данных. `scripts\install-autostart.ps1`
делает это сам, так что в `publish\` секретов не остаётся.

## Команды в чате

| Команда | Что делает |
|---|---|
| любой текст | задача агенту |
| `/menu` | меню настроек кнопками — см. ниже |
| `/new` | новая сессия, контекст сбрасывается |
| `/stop` | прервать текущий запуск (незавершённый ход продолжится со следующим сообщением) |
| `/status` | папка, модель, effort, уровень доступа, id сессии, остаток тарифа, очередь |
| `/project` | сменить репозиторий |
| `/sessions` | список сессий проекта и переключение между ними |
| `/usage` | остаток тарифных окон и расход: запуски, ходы, токены |
| `/model sonnet\|opus\|haiku\|reset` | сменить модель |
| `/effort low\|medium\|high\|xhigh\|max\|reset` | сколько модели думать |
| `/mode` | показать уровень доступа агента к машине |
| `/mode plan\|default\|acceptEdits\|auto\|reset` | сменить уровень доступа |
| `/rules` | что разрешено без вопросов кнопкой «Всегда» |
| `/rules del <номер>`, `/rules clear` | снять одно правило или все |
| `/audit [n]` | последние записи журнала действий (по умолчанию 20) |
| `/help`, `/start` | справка по командам |

Список команд публикуется в Telegram при старте, так что они видны по кнопке «Меню» в поле ввода.

## Меню настроек — `/menu`

Одно сообщение, которое перерисовывается кнопками, — навигация не засоряет чат.

| Экран | Что меняет |
|---|---|
| 📁 Репозиторий | рабочая папка для `claude`. У каждой папки своя активная сессия, поэтому переключение не смешивает контексты |
| 🧠 Модель | алиас модели: `opus`, `sonnet`, `haiku`, `fable` или «по умолчанию». Полное имя — командой `/model claude-sonnet-5` |
| 🎚 Effort | `--effort`: `low` … `max`. Выше уровень — дольше и дороже ответ, но лучше на сложных задачах |
| 🔐 Доступ | то же, что `/mode` |
| 🧵 Сессии | список сессий текущей папки с темой и числом ходов; выбор подставляется в `--resume` |
| 📊 Статистика | остаток тарифных окон, затем расход шлюза: запуски, ходы, токены (включая кэш), разбивка по дням и моделям |

Выбор ложится в `state.json` и переживает перезапуск. Всё, кроме репозитория и статистики,
применяется со следующего запуска — текущий доигрывает со старыми настройками.

### Сессии

Шлюз ведёт собственный список сессий: id, начало первого сообщения, число ходов, стоимость,
время последней активности. Помнит до 25 сессий на папку, свежие сверху.

Сами сессии живут в Claude Code, а `--resume` работает только в той папке, где сессия создана, —
поэтому список привязан к репозиторию. Кнопка «Очистить» убирает записи только из списка шлюза;
сами сессии остаются на диске и доступны через `claude --resume` в терминале.

Сессия заводится до ответа CLI: id выдаётся шлюзом, поэтому `/stop`, таймаут и падение запуска
ветку не теряют — она уже в списке и продолжится следующим сообщением. Единственное исключение —
битый id: если `--resume` не принят, шлюз сбрасывает сессию и пишет об этом в ответ.

### Статистика

Собирается из ответа CLI: `num_turns`, `usage` и `modelUsage`.

**Суммы в чат не выводятся.** На подписке они ни во что не превращаются: платить за запуски
шлюзу нечем — кредиты он не тратит принципиально (см. ниже). Упереться можно только в окно
тарифа, поэтому в сводке, `/status` и на экране статистики показан его остаток: сколько
процентов окна осталось и когда сброс. Оценка стоимости всё же копится в `state.json` —
её ест дневной предохранитель `Gateway:DailyBudgetUsd`, если вы его включили.

### Тарифные лимиты и кредиты

**Кредиты («extra usage») агенту запрещены.** Когда тарифное окно кончилось, задача не
запускается и ждёт сброса, а не уезжает на платные кредиты:

- перед каждым запуском шлюз читает окна тарифа (пятичасовое, недельные — общее и по моделям)
  эндпоинтом `api.anthropic.com/api/oauth/usage` — тем же, что `/usage` внутри CLI, токеном
  подписки из `~/.claude/.credentials.json`. Окно выбрано на 100% → задача отклоняется
  с временем сброса, очередь снимается;
- недельное окно отдельной модели блокирует только запуски этой моделью: упёрлись в opus —
  `/model sonnet` продолжает работу;
- дочернему процессу уходит `DISABLE_EXTRA_USAGE_COMMAND=1`, так что включить кредиты
  изнутри запуска (`/extra-usage`) агент не может;
- если запуск всё же оборвался на лимите, очередь снимается, чтобы не жечь её на отказах.

Эндпоинт лимитов недокументирован: наружу CLI эти данные не отдаёт ни командой, ни флагом,
и в новой версии он может исчезнуть. Если его не удалось прочитать, шлюз пишет предупреждение
в лог и запуск пропускает — иначе бот замолчал бы целиком.

Совсем убрать риск можно только на аккаунте: claude.ai → Settings → Usage, выключить
usage credits. Пока они включены, шлюз пишет об этом в лог при каждой проверке —
интерактивные сессии Claude Code смогут их потратить, даже если бот не станет.

Отдельный денежный предохранитель остался только в конфиге и по умолчанию выключен:
`Gateway:DailyBudgetUsd` (дневной потолок по оценке стоимости) и `Gateway:RunBudgetUsd`
(уходит в `--max-budget-usd`). Из чата они не меняются.

Слэш-команды самого Claude Code (`/review` и любые кастомные из `.claude/commands`)
передаются агенту как есть.

Сообщения, пришедшие во время работы агента, встают в очередь и обрабатываются по порядку.

## Настройки — `Gateway`

| Ключ | Назначение |
|---|---|
| `BotToken` | токен от @BotFather |
| `AllowedUserIds` | Telegram user id, которым можно управлять агентом |
| `ProjectPath` | рабочая папка по умолчанию для `claude` |
| `Projects` | папки, между которыми переключает меню; пусто — соседи `ProjectPath` с `.git` или решением |
| `ClaudeExecutable` | путь к `claude.exe`; `null` — автопоиск |
| `Model` | алиас модели по умолчанию; `null` — как в настройках Claude Code |
| `Effort` | уровень усилий по умолчанию (`low` … `max`); `null` — как решит Claude Code |
| `DailyBudgetUsd` | дневной потолок по оценке стоимости; `null` — без ограничения. Из чата не меняется |
| `RunBudgetUsd` | предел стоимости одного запуска (`--max-budget-usd`); `null` — без предела |
| `PermissionMode` | уровень доступа по умолчанию, `default`; из чата меняется `/mode` — см. ниже |
| `McpPort` | порт локального MCP-сервера подтверждений (только `127.0.0.1`) |
| `ApprovalTimeoutMinutes` | сколько ждать нажатия кнопки, потом автоматический отказ |
| `RunTimeoutMinutes` | предельная длительность одного запуска |
| `Proxy` | HTTP-прокси для Telegram API и `api.anthropic.com`, если они недоступны напрямую |

### Уровень доступа — `/mode`

`Gateway:PermissionMode` — это уровень **по умолчанию**. Из чата его меняет `/mode`: выбор ложится
в `state.json`, переживает перезапуск шлюза и применяется со следующего запуска (текущий доигрывает
со старым). `/mode reset` возвращает значение из конфига.

Из чата доступны только `plan`, `default`, `acceptEdits` и `auto`. `dontAsk` и `bypassPermissions`
намеренно недоступны: полностью снять подтверждения можно только правкой `appsettings.Local.json`
на самой машине — иначе доступ к боту означал бы доступ к машине без единой кнопки.

Кнопка «Всегда» выдаёт агенту постоянные разрешения, и они тоже часть уровня доступа: `/rules`
показывает накопленное, `/rules del <номер>` снимает одно правило, `/rules clear` — все.

### `PermissionMode` — почему он задаётся явно

Шлюз всегда передаёт CLI `--permission-mode`. Без этого действует `permissions.defaultMode`
из `~/.claude/settings.json`, а он у вас стоит в `auto`: решения принимает классификатор,
и карточки с кнопками в чат не приходят вовсе.

| Значение | Поведение |
|---|---|
| `default` (по умолчанию) | всё, что не разрешено правилами из `settings.json`, спрашивается кнопками |
| `acceptEdits` | правки файлов проходят молча, остальное — кнопками |
| `auto` | решает классификатор, кнопки почти не появляются |
| `plan` | агент только исследует и планирует, не меняет файлы |

`bypassPermissions` в вашем случае недоступен: в `settings.json` стоит
`permissions.disableBypassPermissionsMode: "disable"`.

Ваши существующие `allow`-правила продолжают работать: `Read(**/*)`, `Bash(git diff*)`,
`Bash(dotnet build*)` и прочие проходят без подтверждения. Правила из `ask`
(`Bash(git push *)`, `Bash(git checkout*)`) наоборот всегда доходят до кнопок.

## Безопасность

Бот даёт доступ к shell на вашем ПК, поэтому:

- `AllowedUserIds` — единственный барьер аутентификации, заполните обязательно;
- Kestrel слушает только `127.0.0.1`, эндпоинт подтверждений закрыт секретным токеном в заголовке
  `Authorization` (в пути он попадал бы в логи запросов); токен генерируется при каждом старте;
- `bypassPermissions` не используется — каждое действие подтверждается вручную;
- жёсткие запреты удобно прописать в `.claude/settings.local.json` папки проекта: `deny`-правила
  срабатывают раньше запроса подтверждения и не обходятся кнопкой:

  ```json
  { "permissions": { "deny": ["Bash(rm *)", "Edit(//C:/Windows/**)"] } }
  ```

- `appsettings.Local.json` — в `.gitignore`.

Кнопка **♾ Всегда** записывает правило в `.claude/settings.local.json` проекта, если CLI прислал
подсказку правила; иначе шлюз запоминает точное действие сам — команду целиком или путь к файлу,
например `Bash(git status)` или `Write(C:/proj/README.md)` — в своём `state.json`. Совпадение
точное: разрешив `git status`, вы не разрешаете `git status && rm -rf .`.

Выданное «Всегда» отзывается из чата: `/rules` показывает список, `/rules del <номер>` снимает одно
правило, `/rules clear` — все. Правила, записанные CLI в `.claude/settings.local.json`, снимаются
там же, в файле.
