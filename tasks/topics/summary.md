# Итоги анализа: темы в личке с ботом

27.10.2026. Здесь — решения, их причины, факты API и находки ревью. Сам план — `plan.md`.

## Почему темы

В одном чате с ботом сообщения разных проектов смешиваются и теряются. Проект меняется
только через `/project`, а параллельной работы нет. Тема изолирует сессию внутри диалога с
ботом: у каждой темы своя лента, своя сессия и свой выбор модели, effort и режима.

## Решения и причины

| Решение | Причина |
| --- | --- |
| Темы в личке, не в группе | барьер безопасности остаётся прежним. В группе нужна новая защита от посторонних, предел — 20 сообщений в минуту, нет `sendMessageDraft` |
| Темы создаёт и удаляет пользователь в Telegram | клиент это уже умеет. Своих команд у шлюза меньше |
| Тема — отдельный `ChatId` | адресация уже идёт через `ChatId`: `RunScope.Chat`, `ActiveRun.ChatKey`, `inbox\<chat>`, журнал. Ответы сами попадают в тему |
| `TopicState` с путём, сессией, моделью, effort и режимом | требование: каждая тема — отдельная сессия со своей моделью и effort. Режим — тот же механизм, лишней работы нет |
| `Path = null` — беседа | нет отдельного поля «тип», которое разойдётся с путём |
| Тема без записи работает как беседа | команда в новой теме не трогает чужой проект. Нет пустого состояния «без проекта» |
| Полоса на чат и замок на папку | `/stop` и `IsBusy` нужны по чату. Замок не даёт двум запускам править одну папку |
| `WebOnly` вместо нового `AgentRunKind` | `/context` и `/compact` в беседе получают те же ограничения без новых веток |
| Беседа без записи на диск | доверие к проекту у беседы не спрашивается. Без инструментов записи хук в папку не положить |
| Модель беседы по умолчанию — `Gateway:Question` | требование: модель как у вопроса, сейчас `sonnet` |

## Отклонённые варианты

- **Группа с темами** — см. таблицу выше. Запасной вариант, если темы в личке не заработают.
- **Отдельный бот на каждый проект** — код не меняется, но на каждый проект нужен свой
  токен, свои порты, своя папка данных и свой автозапуск.
- **Один чат с ответами на сообщения** — параллельной работы нет.
- **Приложение Claude для бесед** — пользователь хочет беседы в шлюзе.
- **Полоса на папку вместо замка** — проект читается в момент запуска, тема может сменить
  проект, пока задача ждёт. `/stop` и `IsBusy` всё равно нужны по чату.
- **Запрет двух тем на один проект** — оставляет записи удалённых тем, которые держат проект.
  Отдельные сессии темы и замок решают задачу проще.

## Факты Telegram Bot API

Библиотека `Telegram.Bot` 22.10.3 соответствует Bot API 10.3. Обновлять её не нужно.

| Версия | Что появилось |
| --- | --- |
| 6.3 (05.11.2022) | темы в супергруппах: `message_thread_id`, `is_topic_message`, `createForumTopic`, `editForumTopic`, `closeForumTopic`, `deleteForumTopic` |
| 9.3 (31.12.2025) | темы в личке: `User.has_topics_enabled` (в `getMe`), `message_thread_id` в личке, `editForumTopic` и `deleteForumTopic` в личке, `sendMessageDraft` |
| 9.4 (09.02.2026) | `createForumTopic` в личке, `User.allows_users_to_create_topics`. BotFather может запретить пользователю создавать и удалять темы |
| 9.5 (01.03.2026) | `sendMessageDraft` для всех ботов |
| 10.0–10.3 | черновик с пустым текстом, `sendRichMessageDraft`, `can_stop`, `keep_on_stop` |

Ещё факты:

- Темы в личке включает владелец бота в BotFather. Пользователь включил их для
  @arrma_ai_2_bot.
- Удаление темы пользователем не даёт боту никакого события. Бот узнаёт об этом только по
  ошибке при отправке.
- `CallbackQuery.Message` — `MaybeInaccessibleMessage`. У доступного `Message` есть
  `MessageThreadId`. У `InaccessibleMessage` темы нет.
- Предел отправки в личке — около 1 сообщения в секунду на чат. Все темы лички делят его.
- `SendChatAction(chatId, action, messageThreadId, …)`,
  `CreateForumTopic(chatId, name, iconColor, iconCustomEmojiId, …)`.
- `EditMessageText`, `DeleteMessage` и `AnswerCallbackQuery` тему не принимают — она не нужна.

Не подтверждено, проверить на пробе:

- какие клиенты Telegram показывают темы в личке;
- есть ли в личке лента без темы;
- работает ли `closeForumTopic` в личке;
- текст ошибки при отправке в удалённую тему;
- сколько тем можно создать;
- есть ли `MessageThreadId` в нажатии кнопки в теме лички.

## Находки ревью по коду

Независимое ревью проверило версию 3 плана по коду. Все находки учтены в версии 6.

| Важность | Находка | Как учтено |
| --- | --- | --- |
| высокая | замок вокруг `agent.RunAsync` (`ChatWorker.cs:299`) ломает сессию: вторая тема затирает активную сессию первой (`SessionStore.cs:420`) | замок сразу после цикла доверия (после стр. 183), до модели и лимита, отпуск после `SettleSession` (стр. 343). Отдельная сессия у темы снимает и сам конфликт |
| высокая | `ISettingsScreen.RenderAsync/RenderFramesAsync/Open` получают только `UserId`. Меню в теме показало бы проект ленты | интерфейс получает `ChatId`. Координатор и 9 экранов меняются |
| высокая | `ApprovalBroker.cs:224` строго сравнивает `press.Chat` с чатом карточки. Без темы в нажатии карточка в теме зависнет до таймаута, меню изменит проект ленты | проба проверяет `MessageThreadId` в нажатии. Запасной ход: канал запоминает «сообщение → тема» |
| высокая | `ExecuteAsync` запускает ровно 2 потребителя. `RunCts` ставится только на стр. 297, поэтому `/stop` не прервёт ожидание замка | потребитель создаётся при первой задаче. Токен отмены ставится до ожидания замка |
| высокая | у полосы вопросов нет чата. `HasPending` и `CancelAll` глобальные | чат идущего вопроса хранится в полосе. `Cancel(chat)` и `HasPending(chat)` в брокере |
| средняя | `RunMonitor.RunFinished` одного запуска стирает текущий запуск и шаги другого | у текущего запуска есть владелец |
| средняя | `ActiveRun` в старом формате нужен после обновления. `StartupNotice` шлёт полный текст «запущен» в каждую тему | старое поле читается и переезжает. «Запущен» — только в ленту |
| средняя | `ActiveSessions` по пути: две темы с одним проектом делили бы сессию | активная сессия темы живёт в `TopicState` |
| средняя | беседа: очистка папки до цикла доверия, признак по итоговой папке, отказ картинке до скачивания, строгая проверка пути перед удалением | всё — в таблице изменений плана |
| средняя | `/context` и `/compact` в беседе шли бы без ограничений | признак `WebOnly` действует у любого вида запуска |
| низкая | `ReplyToMessage` в теме может указывать на служебное сообщение создания темы | такой ответ не считается ответом. Проба проверяет |
| низкая | `/rules` ходит через `ProjectPathLocked` | методы правил получают чат |
| низкая | `ScreenNavigation` по пользователю | ограничение: позиция в списках общая |
| низкая | CLAUDE.md говорит «два процесса `claude` разом» | правится на этапе 6 |
| низкая | одна цепочка `_groupFlush` задерживает `/stop` из другой темы на окно альбома (1,2 с) | принято, не правим |

Объём: вызовы `SessionStore` — около 65 строк в 21 файле. `IsBusy` — 13 мест в 9 файлах,
`QueueLength` — 3, `Stop()` — 3, `Enqueue` — 4 вызывающих.
